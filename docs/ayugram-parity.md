# AyuGram feature parity for macOS

The behavior reference is the local `AyuGramDesktop` checkout at `d45ed3d102868d7f492a2f6d5f63319fbc74cbf7`, which includes the Telegram Desktop 7.3.1 merge `9e5d4d0d1e`. The public AyuGram Desktop release `v7.2.9` at `d4b7546e77f93ac4c9bb53a3fcf7e9ffbbecf1b5` provides a secondary reference. The local checkout adds behavior and fixes beyond that public release. The feature target is the behavior available on macOS, including local fork changes. AyuGram4A is an optional reference for shared behavior and Android-only ideas.

Every row below is planned and has source evidence from the reference checkout, public documentation, or both. Source evidence establishes what to investigate. Verification requires exercising the reference and the native fork on matching fixtures. Before closing a row, record the pinned native upstream revision, the exact entry point, the supported configurations, and the verification result. Credit existing native upstream equivalents when they pass the same acceptance criteria. Grouped rows cover several controls and each control needs its own check. This inventory has not established runtime parity or exhausted every integration hook.

Source paths below start at `Telegram/SourceFiles/` in AyuGram Desktop unless a full path is given.

## Telegram API and distribution

Telegram's current API terms require separate API credentials and clear third-party branding. Section 1.4 explicitly covers ghost/read controls, presence, typing and preservation of self-destructing content. Section 3.3 requires support for official sponsored messages in channels. AyuGram documents additional points of conflict. Track these behaviors in the inventory, use isolated fixtures for research and treat release decisions separately from verifying technical parity. Review content permissions before distributing features that override copy, forwarding, saving or expiry controls. Local presentation and actual server-side Premium entitlements are distinct.

Use synthetic messages, media and archives for automated and manual QA. Account credentials, personal chat material, media and copied client profiles stay outside the repository. Retention, clearing and account isolation need explicit verification for archive work. Local transcription can use fixtures with clear permission, and external providers should disclose which message data they receive before use.
